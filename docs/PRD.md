# TBox 产品需求文档（PRD）

| 项目 | 内容 |
| --- | --- |
| 产品名称 | TBox（桌面工具箱） |
| 版本 | v2.4.1 |
| 平台 | Windows 10 1809+ / Windows 11（x64） |
| 技术栈 | WinUI 3（Windows App SDK 1.7）+ .NET 8 |
| 最后更新 | 2026-11-06 |

---

## 1. 背景与问题

日常开发会积累大量**自研或便携小工具**：自己写的 exe、绿色版工具、批处理、系统管理面板（.msc）、内部链接。直接丢桌面会形成「快捷方式堆」：

- 桌面被占满，找东西靠肉眼扫描；
- 快捷方式没有分类，也没有说明，过一段时间连自己是干什么的都忘了；
- 便携工具依赖 exe 同级目录的配置，从别处启动会出错；
- exe 被移动后留下死链接，点了才报错。

淘宝式的「桌面收纳格」产品（如 DeskBox）解决了摆放问题，但功能极重（文件管理、待办、天气、音乐、云同步…），对本场景属于过度设计。

**TBox 只做一件事：把零散的小工具收进一个盒子，分类、可搜、随叫随到。**

## 2. 产品目标

1. 桌面从「几十个图标」变成一个入口（托盘 / 热键 / 屏幕边缘的胶囊）。
2. 添加成本 < 5 秒：拖进来即可，图标、名称、启动路径自动完成。
3. 启动行为忠实于原快捷方式：工作目录、参数、管理员标记不丢。
4. 视觉是原生 Windows 11 质感：DWM 圆角、亚克力背板、深浅色跟随系统。
5. 工具变多后仍找得到：**名称、描述、关键字**三处可搜。
6. 数据 100% 本地，无账号、无网络请求、无遥测。

## 3. 非目标（v2.0 明确不做）

| 不做 | 原因 |
| --- | --- |
| 文件/文件夹收纳、拖拽搬运 | 资源管理器的职责，做不好反而危险 |
| 待办、便签、天气、音乐 | 偏离核心场景 |
| 全局文件搜索 | 已有 Everything / PowerToys Run |
| 云同步 / 账号 | 单机工具，本地 JSON 足够 |
| MSIX 打包安装 | 当前构建环境不具备打包工具链（见技术文档），以绿色目录分发 |
| 多语言 | 目前仅简体中文 |

## 4. 用户与场景

**典型用户**：Windows 上的开发者 / IT 运维 / 重工具使用者。

- **收编桌面**：把快捷方式拖进盒子；或「从桌面导入」批量勾选。
- **分类**：标签页分组，卡片可移到其它分组。
- **随叫随到**：贴边收起成胶囊 → 点图标直接启动；或 `Ctrl+Alt+T` 弹出完整面板。
- **靠描述找东西**：只记得"抓串口报文的那个"，搜 `串口` 就能定位，因为描述和关键字也参与匹配。

### 6.3 胶囊（收起态）

竖排（左右贴边，默认）：

```
┌────┐
│ 🐼 │  ← 第 1 个工具
│ 🅉 │  ← 第 2 个
│ 🐳 │  ← 第 3 个
├────┤
│ ‹  │  ← 展开条（点击或悬停）
└────┘
```

横排（顶边自动，也可手动选择）：

```
┌──────────────────┐
│ 🐼  🅉  🐳  │ ‹ │  ← 右侧为展开区
└──────────────────┘
```

- 竖排胶囊 56 DIP 宽、高度随图标数；展开条在底部。
- 横排胶囊 56 DIP 高、宽度随图标数（最多 3 个图标）；展开区在右端。
- 顶边竖条为 16 DIP 高的水平细条，悬停面板向下滑出。

## 7. 数据与存储

位置：`%APPDATA%\TBox\`（可用 `TBOX_DATA` 环境变量覆盖）

```
TBox\
├─ data.json          设置、分组、工具
├─ data.bak.json      上次保存的备份
├─ icons\             图标缓存（{itemId}.png）
└─ error.log          异常日志（如有）
```

`data.json` 关键结构：

```jsonc
{
  "version": 2,
  "settings": {                     // 全局
    "theme": "System",              // System | Light | Dark
    "minimizeToTray": true,
    "runAtStartup": false,
    "activeBoxId": "b1"
  },
  "boxes": [{
    "id": "b1",
    "name": "开发",
    "settings": {                   // 每盒子
      "lastGroupId": "g1",
      "dock": "Right",              // None | Left | Right | Top
      "dockWidth": 420,             // 左右贴边、关闭自适应时的恢复宽度
      "collapsedStyle": "Capsule",  // Capsule | Strip
      "capsuleOrientation": "Auto", // Auto | Vertical | Horizontal
      "autoFitWindow": true,
      "autoFitMaxRows": 4,
      "pinned": false                 // 钉住：不自动收起、重启保持展开
    },
    "window": { "x": 100, "y": 120, "width": 420, "height": 520 },
    "groups": [{
      "id": "g1",
      "name": "我的工具",
      "capsuleItemIds": ["a1b2c3"],   // 固定到胶囊的工具 ID，空数组=前3个
      "items": [{
        "id": "a1b2c3",
        "name": "串口调试助手",
        "path": "D:\\Tools\\Serial.exe",
        "description": "抓 Modbus 报文",
        "keywords": "串口 调试 RS232",
        "workDir": "D:\\Tools",
        "resolvedTarget": "D:\\Tools\\Serial.exe"
      }]
    }]
  }]
}
```

v1（`version: 1`，工具/设置直接在根节点）读取后自动迁移成一个名为「工具箱」的盒子，并立即写回 v2；
迁移前的文件保留为 `data.bak.json`。超过 4 个盒子的文件只加载前 4 个，多余数据不删除；更高版本的文件只读启动。

写入策略：变更后 400ms 防抖，临时文件 + 原子替换，保留一份 `.bak`。

## 9. 验收标准（v2.0）

1. 拖入 10 个不同类型快捷方式，图标与名称正确，双击均可启动。
2. 依赖同级目录的便携工具从盒子启动后正常工作。
3. exe 改名后重启，卡片显示失效角标，状态栏计数正确。
4. 新建分组、拖拽排序、搜索、重命名、删除后重启，状态一致。
5. 切深/浅色，面板、胶囊、对话框全部跟随，无需重启。
6. 拖到屏幕右缘或上缘 → 吸附预览 → 松手收起成胶囊；顶边自动横排；点胶囊图标直接启动；悬停展开区展开。
7. 隐藏到托盘后 `Ctrl+Alt+T` 可弹出；重复启动不产生第二个进程。
8. 断网状态下所有功能可用。
9. 旧 v1 数据启动后变成一个「工具箱」盒子，原分组、窗口位置、贴边/胶囊/自适应设置保留，`data.bak.json` 仍是 v1。
10. 创建到 4 个盒子；托盘可切换/重命名/删除，标题栏显示盒子名；第 5 个新建置灰；最后一个不可删；重启后盒子、活动项、贴边/尺寸状态一致。
11. 两个盒子分别贴左边/顶边，各自收起为竖排/横排胶囊；改一个盒子的收起形态或自适应不影响另一个；切主题时所有窗口同时跟随。
12. 4 盒空闲 10 秒 CPU 接近 0，工作集低于 350MB；只有一个停靠轮询在跑。

## 11. 风险

| 风险 | 对策 |
| --- | --- |
| 热键被占用 | 设置里显示状态；托盘/胶囊兜底 |
